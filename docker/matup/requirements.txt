# NOTE: there is NO hardware incompatibility here. torch 2.0.0 ships CUDA 11.7
# wheels, and CUDA 11.1+ supports Ampere (sm_86), so the pinned versions are
# fine on a 3080 Ti. Every change below is "time rot" instead: upstream left
# these unpinned in 2024 and they resolve to different versions today.

# CHANGED: was `numpy`.
# torch 2.0.0 is built against the NumPy 1.x C ABI. This image is Python 3.10,
# where numpy 2.x IS installable, so scikit-image/pandas can drag it in and
# break torch at import time.
numpy<2
# CHANGED: was `opencv-python`.
# This was ALREADY resolving to 4.x, but only as a side effect of `numpy<2`
# above: the opencv 5.x wheels for this Python require numpy 2, so pip
# backtracked off them. That coupling is invisible and load-bearing - retarget
# the numpy pin later and opencv silently jumps a major version with it. Pin it
# directly so 4.x is intentional rather than incidental.
# Measured before the pin: 4.11.0.86.
opencv-python<5
