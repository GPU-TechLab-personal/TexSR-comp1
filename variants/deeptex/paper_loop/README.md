# variants/deeptex/paper_loop/

The one DeepTextures trainer every arm of ours trains with: the paper's training
loop, with hook calls at the lines an experiment needs to change. An experiment
is a hook bundle (`fixed/hooks.py`, `render_loss/hooks.py`); the loop itself
stays upstream's.

## Contents

| file | what it does |
|---|---|
| `loop.py` | `external/DeepTextures/train_esrgan.py` top to bottom with hook calls inserted; no other line differs (see `upstream.diff`) |
| `psnr_loop.py` | the donor's PSNR stage, `external/esrgan-tf2/train_psnr.py`, the same way (`psnr_upstream.diff`); drives DeepTextures' `modules` |
| `hooks.py` | `Hooks` / `PsnrHooks`: one method per replaced upstream line, and every default **is** that line |
| `main.py` | `--experiment {paper,fixed,render}`: builds the experiment's hook bundle from the rest of the argv and runs `loop.py` or `psnr_loop.py` with it |
| `upstream.diff`, `psnr_upstream.diff` | the committed unified diffs upstream -> ours, regenerated by `variants/tests/l0_skeleton.py --write` |

## How it works

`main.py` puts the repo on `sys.path`, calls `variants.util.paths.use_deeptex()`
(so `import modules.*` is DeepTextures'), then:

| `--experiment` | hooks | loop |
|---|---|---|
| `paper` | `paper_loop/hooks.py` defaults | `loop.py`, through absl `app.run`: exactly `train_esrgan.py` |
| `fixed` | `variants/deeptex/fixed/hooks.py` | `psnr_loop.py` for `--stage psnr`, `loop.py` for `--stage esrgan` |
| `render` | `variants/deeptex/render_loss/hooks.py` | `loop.py` |

For `fixed` and `render`, `main.py` sets `TF_CPP_MIN_LOG_LEVEL=2` before
TensorFlow is imported, the experiment module's `build(argv)` parses the rest of
the argv and returns `(hooks, loop name)`, and the loop reads `--cfg_path` /
`--gpu` from absl `FLAGS` as upstream does. The `paper` entry is not how the
paper arm is trained: that arm runs the submodule's own `train_esrgan.py`
through `variants/deeptex/upstream_runner/`.

### hooks_common/ - the shared trainer machinery

`variants/deeptex/hooks_common/` (no README of its own) holds what both
experiments add to the loop whatever the experiment. `fixed/hooks.py` and
`render_loss/hooks.py` subclass `TrainerHooks` / `PsnrTrainerHooks` from it.

| file | what it does |
|---|---|
| `trainer.py` | `TrainerCore` + `TrainerHooks` (ESRGAN loop) / `PsnrTrainerHooks` (PSNR loop): the common flags (`add_common_args`), CLI overrides, start-up checks, checkpoint/log roots (default `/workspace/runs/deeptex/{checkpoints,logs}`), validation set-up, `[metrics]` / `[val]` reporting, NaN exit, final save |
| `ckpt.py` | `restore`: resume with `assert_existing_objects_matched()`; pretrain from `cfg['pretrain_dir']`, exit 9 if absent, proven by a generator-weight delta. `weights_sha`: 16-hex sha256 of all weights (the `[init]` line) |
| `safety.py` | `die(code, msg)` and the `[fatal]` start-up checks: dataset (meta, size, `verify_report.json`), GPU (+ matmul timing), disk, output root, `gt_size`, dead LR schedule |
| `seed.py` | `apply_seed`: `tf.keras.utils.set_random_seed` when a seed is given (fixes the Keras initialisers too); unseeded otherwise, as upstream |
| `log.py` | the newline-terminated `[metrics]` line (`MetricsWindow`) and the `[terms]` line |
| `val.py` | held-out validation: PSNR/SSIM of the generator (a dynamic-shape twin) and bicubic on `val_dataset.{hr_dir,lr_dir}` |

## Run

Normally through an arm's `run.ps1` (`variants/deeptex/fixed/run.ps1`,
`variants/deeptex/render_loss/run.ps1`). Directly, in the deeptex container
(`docker compose -f docker/compose.yaml run --rm deeptex ...`; it starts in
`/workspace/external/DeepTextures`, so paths are absolute):

    python /workspace/variants/deeptex/paper_loop/main.py --experiment paper  --cfg_path X [--gpu 0]
    python /workspace/variants/deeptex/paper_loop/main.py --experiment fixed  --stage psnr|esrgan ...
    python /workspace/variants/deeptex/paper_loop/main.py --experiment render ...

For `fixed` and `render`, the flags are `hooks_common/trainer.py
add_common_args` plus the experiment's own `add_args`; `paper` takes only
upstream's absl flags `--cfg_path`, `--gpu`.

After editing `loop.py`, `psnr_loop.py` or `hooks.py`, run on the host

    python variants/tests/l0_skeleton.py           # loop files = upstream + hook calls only
    python variants/tests/l0_skeleton.py --write   # also regenerate the two .diff files

## Contracts and known behaviour

* **Log prefixes and exit codes are parsed** by the run.ps1 files
  (`Get-FailureKind`, `Assert-TrainingReached` in `variants/util/lib.ps1`):
  `[metrics]`, `[terms]`, `[render]`, `[val]`, `[init]`, `[*] resumed from`,
  `[fatal]`. Exit codes: 2 output root, 4 non-finite loss, 5 dataset, 6 no GPU,
  7 disk, 8 config / flag, 9 pretrain (`hooks_common/safety.py`).
* Checkpoint object names (`step`, `model`, `discriminator`, `optimizer_G/D`,
  `optimizer`) and config keys are upstream's, so existing checkpoints restore.
* RNG consumption order with a seed: seed -> `check_gpu` -> G -> D -> dataset ->
  optimizers -> `ContentLoss` -> `RenderLoss`. Anything inserted before the model
  build changes the init.
* **TensorBoard tags** are upstream's: the ESRGAN loop writes
  `train_esrgan.py:131-144`'s, the PSNR loop the donor's `loss/*`,
  `learning_rate`. Our own scalars (`val/*`, `monitor/render_l21`) go through a
  second writer to the same log directory.
* The render arm's `--losses`, `--shuffle` accept only `upstream` / `off`; the
  fixed arm has no render flags, so `--w-render` on it is an argparse error
  (exit 2). `--experiment render` on a non-grouped config and `--experiment
  fixed` on a grouped one both exit 8.
